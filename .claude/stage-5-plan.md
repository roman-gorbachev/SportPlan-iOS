# Этап 5: активная тренировка — план

Объём — `docs/code-brief.md`, раздел 3 «Активная тренировка и история подходов». Решения — `.claude/decisions.md` («Этап 5»). Макеты — `.design/screens/WorkoutScreen` (состояния active / start / empty / ax), `ActiveDark`, `StartLight/Dark`, компоненты — `.design/system/WorkoutKit`.

## Решения обсуждения (18.11.2026)
- Два блока: 5.1 — Domain и data, 5.2 — экраны. Коммиты отдельно, между ними можно остановиться.
- Раскладка блинов — чистая доменная функция на этапе 5, стопка в строке подхода рисуется сразу. Редактор блинов и сброс к IWF — этап 8.
- Таймера отдыха на этапе 5 нет: `rest_started_at` / `rest_ends_at` не пишутся, отдых в строке — только цель. Таймер, accessory и уведомление — этап 6.
- В этап входят: тренировка вне плана, «Добавить упражнение» и «Отменить тренировку» в меню «…», подписи «следующий — B» и «пн 16.11».
- Не входят: бейдж рекорда (этап 9), подсказка прогрессии (этап 10), Live Activity (этап 7).
- Схема v1 покрывает всё, новых миграций нет.

## 5.1 Domain и data

### Domain (`Packages/SportplanKit/Sources/Domain/`)
- **Модели:**
  - `ActiveWorkout` — тренировка и `[ActiveWorkoutExercise]` по `position`;
  - `ActiveWorkoutExercise` — `WorkoutExercise`, `LibraryExercise` (упражнение с оборудованием), `[SetEntry]` по `position`, прошлый результат (`[SetEntry]` рабочих подходов последней завершённой тренировки с этим упражнением);
  - `SetEntryState` — выводится, не хранится: `planned` (нет `completedAt`), `running` (секундомер: есть `startedAt`, нет `completedAt`), `completed`;
  - `SetEntryDraft` — вес, повторы, длительность, разминка; валидация по метрике: повторы ≥ 0 у «Повторов», длительность у «Времени»;
  - `PlateLoading` — результат раскладки: блины на сторону по убыванию и остаток, который нельзя набрать;
  - `NextProgramDay` — для программы: следующий день и дата последней тренировки по каждому дню;
  - `WorkoutError`: `alreadyActive`, `noActiveWorkout`, `notFound`, `exerciseAlreadyInWorkout`, `invalidSet`.
- **Чистая логика** (функции на моделях или `enum` с `static`, всё `nonisolated`, тесты в пакете):
  - **плановые строки при старте по дню**: на каждое упражнение дня `targetSets` строк. Значения — рабочие подходы прошлой тренировки с этим упражнением по номеру; если их меньше — повторяется последний; если истории нет — вес из оборудования (гриф / база тренажёра, у гантелей и своего веса 0), повторы — нижняя граница цели, у «Времени» длительность пустая;
  - **упражнение без плана** (вне плана или добавленное по ходу): строки как рабочие подходы прошлой тренировки с ним; если истории нет — одна строка по тем же правилам;
  - **«как предыдущий»**: значения предыдущей строки упражнения;
  - **степперы**: вес ± `weightStep` оборудования, у своего веса ± 2,5 кг (`private static let`), не ниже базового веса; повторы ± 1, не ниже 0;
  - **раскладка блинов**: на сторону `(вес − базовый вес) / 2`, жадно по блинам зала от тяжёлого, каждый блин без ограничения количества; только для штанги и тренажёра с блинами; остаток > 0 показывается в UI;
  - **следующий день программы**: день после дня последней завершённой тренировки этой программы по `position`, по кругу; без тренировок — первый день; если тот день удалён — первый;
  - **«Завершить»**: невыполненные строки удаляются; упражнения без единого выполненного подхода тоже удаляются; если не осталось ни одного выполненного подхода — тренировка удаляется целиком (как «Отменить»). Последнее — вопрос к ревью.
- **`Repository/WorkoutRepository`:**
  - `observeActive() -> AsyncThrowingStream<ActiveWorkout?, any Error>`;
  - `start(_ workout: Workout, exercises: [WorkoutExercise], sets: [SetEntry])` — одна транзакция; вторая активная отклоняется уникальным индексом → `alreadyActive`;
  - `addExercise(_:sets:)`, `addSet(_:)`, `updateSet(_:)`, `removeSet(id:)`, `updateNote(workoutId:note:)`;
  - `finish(workoutId:at:)` — удаление невыполненного и `finished_at` в одной транзакции; `cancel(workoutId:)`;
  - `lastWorkingSets(exerciseId:) async throws -> [SetEntry]` — рабочие выполненные подходы последней завершённой тренировки с упражнением;
  - `lastWorkoutDates(programId:)` — для «следующего дня» и «пн 16.11».
- **`Repository/PlateRepository`** — `plates() async throws -> [Plate]` (только чтение; правка — этап 8).
- **Use cases (`UseCase/Workout/`), у каждого один `execute`:**
  - `ObserveActiveWorkoutUseCase`;
  - `StartWorkoutFromDayUseCase(dayId:)` — снимок дня (название, метка), копия целей и отдыха из `planned_exercise`, плановые строки; часы и генератор UUID через init;
  - `StartEmptyWorkoutUseCase`;
  - `AddExerciseToWorkoutUseCase(exerciseId:)` — дубль в тренировке запрещён, как в дне;
  - `AddSetUseCase` (копия предыдущей, флаг разминки), `UpdateSetUseCase` (черновик, валидация), `CompleteSetUseCase` (`completedAt` = сейчас), `StartTimedSetUseCase` / `StopTimedSetUseCase` (секундомер: `startedAt`, затем `durationSeconds` = разница, `completedAt`), `RemoveSetUseCase`;
  - `UpdateWorkoutNoteUseCase` — пустая после trim заметка → `nil`;
  - `FinishWorkoutUseCase`, `CancelWorkoutUseCase`;
  - `ObserveProgramScheduleUseCase` — следующий день и даты для вкладки «Программы» и экрана старта;
  - `LoadPlatesUseCase` → раскладка для веса и оборудования.
- **Тесты (`DomainTests`):** `FakeWorkoutRepository` на `Mutex`; плановые строки (история длиннее, короче, нет; повтор последнего; время); строки без плана; степперы и границы; раскладка (ровно, с остатком, вес меньше грифа, 1,25 кг); следующий день (нет истории, по кругу, удалённый день); «Завершить» (удаление невыполненного, пустая тренировка); старт при активной → `alreadyActive`.

### Data (`sportplan/data/repositories/`)
- `WorkoutRepositoryImpl` (`nonisolated`, `AppDatabase`): наблюдение активной тренировки одним `ValueObservation` (тренировка, упражнения с упражнением и оборудованием, подходы, прошлый результат по каждому упражнению). Прошлый результат — запрос по `workout_exercise` + `set_entry` последней тренировки с `finished_at IS NOT NULL`, `is_warmup = 0`, `completed_at IS NOT NULL`.
- `PlateRepositoryImpl` — чтение `plate`.
- `ProgramRepositoryImpl` / `ProgramSummary` дополняются датой последней тренировки дня (или отдельный запрос в `lastWorkoutDates`) — выберу при реализации, без изменения схемы.
- **Тесты (`sportplanTests/data/WorkoutRepositoryImplTests`):** старт пишет снимок и строки, вторая активная отклоняется; наблюдение отдаёт упражнения и подходы по порядку; прошлый результат берёт последнюю завершённую тренировку и пропускает разминку и невыполненные; «Завершить» удаляет невыполненное; «Отменить» удаляет всё; удаление дня программы оставляет снимок в тренировке.

## 5.2 Экраны (`sportplan/presentation/workout/`)
- **Владелец состояния**: `ActiveWorkoutStore` в `AppDIContainer` (один на приложение) держит наблюдение `ObserveActiveWorkoutUseCase`; его читают вкладка «Тренировка», позже accessory таймера (этап 6) и Live Activity (этап 7). Экранные ViewModel получают данные от него через use case, к репозиторию не ходят.
- **Вкладка «Тренировка»** (`WorkoutTabView` вместо заглушки): нет активной → экран старта; есть → активная тренировка. Шестерёнка настроек остаётся.
- **Старт** (`start/`): программы с днями, у каждой отмечен следующий день («следующий — B»), у дней «пн 16.11» / «ещё не было»; тап по дню — старт; «Пустая тренировка». Без программ — пустое состояние из макета (`empty`).
- **Активная тренировка** (`active/`): заголовок — день или «Тренировка», время начала; упражнения со строками подходов по макету `WorkoutKit`:
  - строка: номер или «Р» у разминки, вес × повторы / длительность, стопка блинов, прошлый результат рядом, состояния из макета;
  - тап по строке — правка: степперы веса и повторов, «как предыдущий», «Выполнено»; у «Времени» — секундомер «Старт / Стоп» (`TimelineView` от `startedAt`, переживает перезапуск);
  - «+ Подход», «+ Разминка», swipe — удалить подход;
  - заметка — поле внизу;
  - меню «…»: «Добавить упражнение» (picker из 4.2 в режиме тренировки), «Отменить тренировку» с подтверждением;
  - «Завершить» с подтверждением, если есть невыполненные строки («N невыполненных подходов будут удалены»).
- **Вкладка «Программы»**: в `ProgramDayRow` вместо числа упражнений — «пн 16.11» / «ещё не было», у программы — «следующий — B», как в макете списка.
- **DesignSystem**: `PlateStack` (стопка по цветам блинов из БД, высота по весу блина), `SetRow` — если компонент общий с историей (этап 11); иначе в presentation.
- **Строки**: всё через String Catalog, плюралы «N подходов».
- **Тесты ViewModel**: старт по дню создаёт строки; «как предыдущий»; степпер не уходит ниже базы; секундомер пишет длительность; «Завершить» и «Отменить».

## Вопросы к ревью плана (моя позиция в скобках)
- **Вес штанги** в подходе — общий, с грифом? (Да: так пишут в зале и так считаются рекорды; стопка показывает только блины на сторону.)
- **Тренажёр с блинами** — блины на две стороны, как у штанги? (Да, по умолчанию; тренажёры с одной стороной — позже, если понадобится флаг в оборудовании.)
- **«Завершить» без единого выполненного подхода** — удалить тренировку, а не сохранять пустую? (Да, пустая тренировка в истории и heatmap — шум.)
- **Повторы по умолчанию без истории** — нижняя граница цели? (Да, цель «8–12» начинается с 8.)
- **Правка выполненного подхода** — тап снова открывает степперы, подход остаётся выполненным? (Да, ошибки при вводе бывают; «отменить выполнение» не нужно.)
