# Бриф для разработки: трекер тренировок (iOS)

## Контекст

Личный pet-проект: минималистичный трекер силовых тренировок для iPhone. Без рекламы, подписки, калорий и аккаунтов. Сначала делается для себя, в будущем возможна публикация в App Store с разовой покупкой (не подпиской).

Главный принцип: **не перегружать**. Новые функции добавлять только по договорённости. Всё, что не перечислено ниже, обсуждаем отдельно. Цель v1 — живое рабочее приложение.

Дизайн делается отдельно (`.design/design-brief.md`). Код должен легко принять токены дизайн-системы: цвета, шрифты, отступы вынесены в одно место.

Разработка идёт этапами, по одному блоку; каждый этап обсуждается перед началом. Полный журнал решений — `.claude/decisions.ru.md`.

## Функции (утверждённый скоуп)

### 1. Оборудование и упражнения
- **Оборудование** — всё железо зала: грифы, гантели, тренажёры. Виды:
  - свободный вес: `barbell` (гриф, в т.ч. EZ и Смит), `dumbbell` (гантели);
  - тренажёры: `plateLoadedMachine` (с блинами), `selectorizedMachine` (блочный).
- У оборудования: название, вес грифа или платформы (`baseWeight`, для блочных и гантелей 0), шаг веса (`weightStep`).
- Зал один: оборудование и блины ни к какому залу не привязаны.
- **Упражнение**: название, необязательное описание (текст), оборудование (если не задано — собственный вес), метрика (`weightReps` — вес × повторы, `duration` — время), отдых по умолчанию (`restSec`, 90 сек).
- Справочник общий для всех программ; при первом запуске пустой, добавление быстрое.
- Упражнения и оборудование **не удаляются, а архивируются**: исчезают из справочника и выбора, история, рекорды и графики остаются. При архивации упражнение убирается из дней программ, подтверждение «будет убрано из N дней».
- Если по упражнению уже есть подходы, метрику менять нельзя, а оборудование — только на оборудование того же вида (иначе старые записи прочитаются по-другому).
- Сценарий добавления упражнения и оборудования определяется дизайном.

### 2. План-программа
- Программа → дни («День A — грудь/трицепс») → упражнения в дне.
- Для упражнения в дне: порядок, целевое число подходов, **диапазон целевых повторов** (min–max; одно число = min == max), время отдыха (по умолчанию берётся из упражнения).

### 3. Активная тренировка и история подходов
- Старт тренировки по дню программы или пустой (вне плана). Активная тренировка одна; она переживает закрытие приложения.
- Цели (подходы, повторы, отдых) копируются в тренировку на момент старта: последующие правки программы историю не меняют.
- **Плановые подходы**: при старте по дню создаётся столько строк, сколько целевых подходов. Значения берутся из рабочих подходов прошлой тренировки с этим упражнением по номеру; если их было меньше, повторяется последний. Разминку добавляешь сам. У тренировки вне плана структура как в прошлый раз.
- Строка подхода — «план» или «выполнено». При «Завершить» невыполненные строки удаляются.
- Запись подхода зависит от упражнения, есть флаг «разминка»:
  - штанга и тренажёр с блинами — вес × повторы, стопка блинов;
  - блочный тренажёр — вес × повторы;
  - гантели — вес одной гантели × повторы;
  - собственный вес — повторы, необязательное отягощение (вес = дополнительный вес, по умолчанию 0);
  - на время — **секундомер**: кнопка запускает счёт вверх, пользователь останавливает, записывается фактическая длительность.
- **Прошлый результат прямо в поле ввода**: подходы этого упражнения из последней тренировки показываются рядом.
- **Повтор подхода одним тапом**: кнопка «как предыдущий», степперы веса (± шаг оборудования; для отягощения своего веса 2.5 кг) и повторов (±1).
- Добавить или удалить подход, добавить упражнение по ходу тренировки.
- **Заметка к тренировке** (текст).

### 4. Таймер отдыха
- **Запускается автоматически** после любого выполненного подхода (включая разминочный). Длительность — отдых упражнения в этой тренировке.
- Можно пропустить, а также добавить или убрать 15 сек.
- Таймер хранит только время окончания и не тикает сам: переживает сворачивание и перезапуск.
- Локальное уведомление о конце отдыха (`UNUserNotificationCenter`), отменяется при пропуске. Разрешение запрашивается при первом запуске таймера; без разрешения таймер работает в приложении и в Live Activity.
- В приложении таймер показывается в `tabViewBottomAccessory` над таб-баром, только во время отдыха.

### 5. Live Activity / Dynamic Island
- Одна Live Activity **на всю тренировку**: стартует вместе с тренировкой, заканчивается по «Завершить».
- Показывает текущее упражнение и подход; во время отдыха — обратный отсчёт через `Text(timerInterval:)`, без обновлений из приложения.
- `staleDate` = конец отдыха → состояние «Отдых окончен», когда приложение в фоне.
- Кнопок в Live Activity в v1 нет.

### 6. Блины
- Набор блинов своего зала: у каждого блина вес и цвет (hex). По умолчанию стандарт IWF: 25 (красный), 20 (синий), 15 (жёлтый), 10 (зелёный), 5 (белый), 2.5 (красный), 1.25 (сталь).
- Добавить, изменить, удалить блин; «Сбросить к стандарту IWF» с подтверждением. Два блина одного веса не допускаются, вес от 0.25 до 50 кг.
- Раскладка на сторону для штанги и тренажёра с блинами: `(вес − вес грифа/платформы) / 2`. **Точный подбор**: блинов каждого веса сколько угодно, выбираем вариант с наименьшим числом блинов, при равенстве — с более тяжёлыми. Если вес меньше грифа или точно не собирается — стопку не показываем; вес равен грифу — пустой гриф.
- Цвет блина используется только в графике стопки. Цвета состояний (рекорд, успех, разминка, удаление) — отдельные токены дизайн-системы.
- Музыки в приложении нет: её закрывает системный плеер на экране блокировки.

### 7. Личные рекорды и график по упражнению
Учитываются только выполненные рабочие подходы. **Разминочные подходы не участвуют** в рекордах, графиках, heatmap и подсказке прогрессии.

| Упражнение | Рекорды | График (точка = тренировка) |
|---|---|---|
| С оборудованием, вес × повторы | Макс. вес; макс. расчётный 1ПМ по Эпли `w × (1 + reps / 30)`, при reps == 1 — w; 1ПМ только по подходам с reps ≤ 12 | Лучший расчётный 1ПМ или макс. вес (переключатель) |
| Собственный вес | Подход — рекорд, если раньше не было подхода, где и отягощение, и повторы не меньше. В карточке: «макс. повторов», «макс. отягощение × повторы» | Макс. повторов |
| На время | Макс. длительность | Макс. длительность |

- Бейдж «новый рекорд» при записи подхода, побившего рекорд. Сравнение со всем, что было до этого подхода, включая текущую тренировку. Повторение рекорда — не рекорд. Если истории по упражнению ещё нет, бейджа нет.
- Графики — Swift Charts.

### 8. Подсказка прогрессии
- Только для упражнений с оборудованием и метрикой вес × повторы.
- Условие: у прошлой тренировки с этим упражнением были цели, рабочих подходов не меньше целевого числа, и в каждом повторов не меньше верхней границы диапазона.
- Предложение: максимальный рабочий вес прошлой тренировки + шаг оборудования.
- Подсказка ненавязчивая: одна строка, тап подставляет вес во все невыполненные рабочие подходы упражнения. Никакой автоматики без участия пользователя.

### 9. Календарь (heatmap)
- Сетка по дням в стиле GitHub на вкладке «История».
- Интенсивность — число выполненных рабочих подходов за локальный день, 5 уровней: 0 / 1–6 / 7–12 / 13–18 / 19+ (подстроим на реальных данных).
- Тап по дню открывает тренировку(и) этого дня.

### 10. Офлайн и данные
- Работает полностью офлайн, сервера нет.
- Локальное хранение в SQLite через GRDB.
- Экспорт и импорт всех данных в JSON (`fileExporter` / `fileImporter` и ShareLink) для бэкапа и переноса. В JSON есть `schemaVersion`; импорт в v1 **заменяет все данные** после подтверждения.

## Структура UI

`TabView`, три вкладки, у каждой свой стек навигации (таймер в accessory виден на любой глубине):
1. **Тренировка**: старт и активная тренировка.
2. **Программы**: программы, дни, упражнения.
3. **История**: heatmap, список тренировок, детали, карточка упражнения (график, рекорды, история).

Плюс настройки: **«Мой зал»** (оборудование и блины), экспорт и импорт.

Только iPhone, только портретная ориентация.

## Стек

- Swift, SwiftUI, Observation (`@Observable`), async/await.
- GRDB 7 (SQLite) — единственная сторонняя зависимость, через SwiftPM («до следующей мажорной»), только в таргете приложения. В приложении `DatabasePool` (WAL) с файлом в Application Support, в тестах in-memory `DatabaseQueue`.
- Swift Charts для графиков.
- ActivityKit и Widget Extension для Live Activity.
- UserNotifications для конца отдыха.
- Swift Testing для тестов.
- Минимальная версия: **iOS 26**.
- Других сторонних зависимостей нет, пока они реально не понадобятся.

## Архитектура

- Слои `presentation → domain → data`, направление зависимостей строгое.
- **Локальный Swift Package**:
  - `Domain` — модели, протоколы репозиториев, use cases, чистые расчёты (1ПМ, рекорды, раскладка блинов, прогрессия, heatmap). Типы `Sendable`, логика `nonisolated`. Тестируется через `swift test` без симулятора.
  - `DesignSystem` — токены (цвета, шрифты, отступы, скругления) и базовые компоненты; общий для приложения и виджета.
- **Приложение**: `presentation/` (фичи: `ui/`, `viewmodel/`, `models/`, `states/`), `data/` (GRDB: `AppDatabase`, записи, репозитории), `di/` (`AppDIContainer` — единственный composition root).
- **Data**: `XRepository` (протокол в Domain) / `XRepositoryImpl` прямо поверх `AppDatabase`, без DataSource. Отдельные классы только для внешних систем: уведомления, ActivityKit, файлы экспорта.
- **Use cases**: ViewModel обращается только к use cases, даже к простым пробросам.
- **Presentation**: ViewModel — `@Observable final class` с `UiState` (`loading` / `success` / `error`); экран — `XRoute` (владеет ViewModel, подписка в `.task {}`) + `XScreen` (чистая View с данными и замыканиями, `#Preview`).
- **Реактивность**: `ValueObservation.values(in:)` → `AsyncSequence`; Combine не используем.
- **Навигация**: `Router` на `NavigationPath`, свой `NavigationStack` и `Router` в каждой вкладке.
- **Состояние тренировки**: активная тренировка — запись `workout` без `finishedAt` в БД; таймер отдыха — сохранённое время окончания; один долгоживущий владелец этого состояния в `AppDIContainer`, его читают вкладка «Тренировка», accessory и Live Activity.
- Правила кода — в `CLAUDE.md` в корне репозитория.

## Модель данных (v1)

Соглашения:
- Ключи — UUID, хранятся текстом (стабильны при экспорте и импорте, читаемы при отладке).
- Вес — целые **граммы** (`INTEGER`), в домене тип `Weight` с форматированием. Переключатель на lb, если появится, не потребует миграции.
- Порядок — `position INTEGER`.
- Даты — UTC; дни для heatmap группируются в Swift по локальному календарю.
- Миграции через `registerMigration`; после появления реальных данных существующие миграции не редактируются, только новые.
- Внешние ключи включены, индексы на все FK явно.

```
equipment          id, name, kind, base_weight_g (0), weight_step_g, is_archived, created_at
                   kind: barbell | dumbbell | plate_loaded_machine | selectorized_machine
exercise           id, name, description?, equipment_id? → equipment RESTRICT,
                   metric (weight_reps | duration), rest_sec (90), is_archived, created_at
program            id, name, position, created_at
program_day        id, program_id → program CASCADE, name, label?, position
planned_exercise   id, program_day_id → program_day CASCADE, exercise_id → exercise RESTRICT,
                   position, target_sets, target_reps_min?, target_reps_max?, rest_sec
workout            id, program_day_id? → program_day SET NULL, program_day_name? (копия),
                   program_day_label? (копия), started_at, finished_at?, note?,
                   rest_started_at?, rest_ends_at?
workout_exercise   id, workout_id → workout CASCADE, exercise_id → exercise RESTRICT,
                   position, target_sets?, target_reps_min?, target_reps_max?, rest_sec
set_entry          id, workout_exercise_id → workout_exercise CASCADE, position,
                   weight_g (0), reps?, duration_sec?, is_warmup, started_at?, completed_at?
plate              id, weight_g UNIQUE CHECK(250…50000), color_hex
```

- Индексы: все FK, `workout(started_at)`, частичный уникальный индекс `workout WHERE finished_at IS NULL` — активная тренировка одна, это гарантирует сама база.
- Удаление или изменение программы не ломает историю: `workout` хранит копию названия и метки дня, `workout_exercise` — копию целей.
- День программы: `name` обязательно («Грудь и трицепс»), `label` — необязательная короткая метка («A»). Без метки везде показывается название.
- Таймер отдыха: `rest_started_at` и `rest_ends_at` у активной тренировки. ±15 с сдвигает конец, «Пропустить» обнуляет оба поля, прогресс «из 2:00» — разница дат.
- Секундомер подхода на время: `set_entry.started_at` пишется при старте, при остановке — `duration_sec` и `completed_at`; переживает перезапуск.
- Блины IWF вставляет миграция v1 из константы в `Domain`; «Сбросить к стандарту IWF» использует ту же константу.
- Рекорды и «прошлый результат» вычисляются запросами и в Swift, отдельно не хранятся (при проблемах с производительностью можно кешировать).
- Глобальных настроек в БД нет; `UserDefaults` — только для мелочей интерфейса.

## Распространение

- Сейчас бесплатный Apple ID (personal team): профиль живёт 7 дней. Переустановка из Xcode поверх текущей версии сохраняет данные; удаление приложения — нет, поэтому важен экспорт. Как вариант, SideStore или AltStore для автопереподписи.
- Лимит бесплатного аккаунта — около 3 приложений, Widget Extension занимает отдельный слот: приложение займёт 2 из 3.
- **Не используем capabilities, недоступные бесплатному аккаунту**: iCloud/CloudKit, push-уведомления, App Groups (для Live Activity не нужны — `ActivityAttributes` компилируется в оба таргета). Локальные уведомления и Live Activity подходят. Time Sensitive уведомления — проверить на этапе таймера.
- Платный Developer Program пока под вопросом (из Беларуси бывают проблемы с оплатой и выплатами).
- Язык: основной русский, все строки через String Catalog; английский — перед публикацией.

## Качество

- Unit-тесты на чистую логику: 1ПМ, рекорды, предзаполнение и прошлый результат, подсказка прогрессии, уровни heatmap, раскладка блинов, экспорт и импорт JSON (round-trip). Репозитории — на in-memory базе.
- Доступность: Dynamic Type, VoiceOver-лейблы, зоны нажатия от 44pt.
- Дизайн-токены (цвета, шрифты, отступы) в модуле `DesignSystem`, чтобы легко подставить дизайн-систему.

## Этапы

0. Решения и документы.
1. Каркас: проект, таргеты, пакет, DI, заглушки токенов, локализация, три вкладки.

## Открытые вопросы (обсудить в процессе)

- Сценарий добавления упражнения и оборудования — по итогам дизайна.
- Название приложения и bundle id — на этапе каркаса.
- Настройки тренажёра (сиденье, спинка) — идея, не в скоупе; место для них — `equipment`.
- Тренажёры с противовесом (гравитрон), где меньший вес тяжелее, — пока не поддерживаем; в будущем отдельный вид.
- Тренажёры с загрузкой на одну сторону (Т-гриф) — в будущем `plate_sides` в `equipment`.
- Суперсеты — в будущем `group_id` на `workout_exercise`.
- Единицы: только кг или переключатель на lb (вес уже хранится в граммах).
